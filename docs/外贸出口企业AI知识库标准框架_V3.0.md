# 外贸出口企业 AI 知识库标准框架 V3.0

> 适用对象：中国出口制造企业、外贸公司、工贸一体企业、跨境 B2B 服务团队。  
> 最小输入：企业中文或英文简介 + 企业官网 URL。  
> 建设目标：AI 先从官网和公开资料生成“可用的第一版”，再通过少量高价值确认问题逐步升级为可信、可执行、可持续迭代的企业知识中台。  
> V2.0 新增：客户分级背调、速查卡与新人路径、行业术语、产品机会池、平台发品与 SEO、沉默诊断、客户挽回、分级售后、案例与周报闭环。
> V3.0 新增：客户资产与老客户知识库、Account/Contact/Opportunity关系模型、9万客户动态评分、复购预警、八类动态名单、自动培育与人工跟进边界。

---

## 0. 核心结论

外贸企业知识库不能只是“公司介绍、产品目录、FAQ”的资料集合。真正可供业务员和 AI 使用的知识库，必须同时回答六类问题：

1. **我们是谁**：公司、品牌、工厂、资质和可信证据。
2. **我们能卖什么**：产品、规格、定制能力、质量与交付边界。
3. **应该卖给谁**：市场、渠道、买家类型、采购角色和购买信号。
4. **哪些客户现在最值得跟进**：把客户历史、采购意向、产品匹配、商机阶段、复购周期、联系人和风险转成动态优先级。
5. **怎样推进成交**：开发、询盘、报价、样品、谈判、订单与售后动作。
6. **如何越用越准**：把询盘、异议、输单、赢单、复购和交付问题持续沉淀回知识库。

本框架采用“双核心、五层、二十一个标准模块、六种岗位视图”：企业知识核心负责“我们是谁、卖什么、怎样卖”，客户资产核心负责“客户是谁、买过什么、现在是否有机会、下一步做什么”。两者通过产品ID、客户ID、商机ID、互动与订单相互连接。

### 0.1 最小输入与预期完成度

| 输入条件 | AI 可生成内容 | 预期初始完成度 |
|---|---|---:|
| 公司简介 + 内容完整的官网 | 公司事实、产品体系、能力、初步 ICP、初步市场与话术 | 60%–80% |
| 再增加产品目录、认证、案例 | 产品字段、合规、证明材料显著增强 | 75%–90% |
| 再确认价格、MOQ、交期、付款等内部政策 | 可直接支持销售执行 | 85%–95% |
| 再接入OKKI/CRM客户、互动、商机和成交数据 | 建立客户360、动态优先级、复购与漏跟进预警 | 客户数据质量决定 |
| 接入询盘、CRM、订单和复盘数据 | 形成动态、自学习知识库 | 持续优化 |

> 完成度是“字段是否具备”的估计，不等于信息真实性。未经企业确认的推测必须保留“待确认”标签。

### 0.2 自动建库的标准交付包

企业只提交公司简介和官网后，系统应交付的不是一篇长报告，而是以下相互关联的资产：

| 交付物 | 作用 |
|---|---|
| 企业知识总库 | 00–20 模块的结构化事实、规则、策略和模板 |
| 企业知识地图 | 公司、产品、市场、买家、证据、流程之间的关联 |
| 业务速查卡 | 主推产品、买家类型、询盘必问、旺季节奏、红线与升级人 |
| 新人学习路径 | 7天或按岗位配置的学习与实战任务 |
| 产品与 ICP 图谱 | 产品—市场—渠道—买家—场景—证据的匹配关系 |
| 客户背调与商机卡 | L1验真、L2价值评估、L3深度背调及下一步动作 |
| 客户资产与老客户库 | Account、Contact、Opportunity、Interaction、Order、Risk、Consent统一关系 |
| 动态优先级与八类名单 | 今日跟进、报价未推进、样品未转单、复购预警、高互动、采购异动、重新活跃、高分漏跟进 |
| 销售执行包 | 询盘、选型、报价、样品、异议、跟进、沉默与挽回模板 |
| 内容运营包 | B2B平台发品、SEO、独立站、社媒与多语言FAQ口径 |
| 风险与审批表 | 价格、账期、免费样、模具、独家、认证、索赔和收款账号红线 |
| 缺口与确认队列 | 按获客、报价、交付三批提出的少量高价值问题 |
| 质量与成熟度报告 | 完整度、来源覆盖率、人工确认率、时效和检索测试结果 |

## 1. 建设原则

### 1.1 先生成，后确认

凡是可从官网、公开目录、公开证书和可信第三方来源获得的信息，由 AI 先提取和组织；涉及底价、毛利、真实产能、付款例外、客户名单、质量事故等内部信息，必须由企业确认，不允许推测。

### 1.2 事实、推断和建议严格分开

每条知识必须属于以下一种状态：

| 状态 | 含义 | 是否可直接对客使用 |
|---|---|---|
| 已验证事实 | 有可靠来源，且已被企业或权威文件确认 | 是 |
| 公开事实 | 来自企业官网或公开材料，尚未人工复核 | 谨慎使用 |
| AI 推断 | 依据公开资料推测，可能不准确 | 否 |
| 建议策略 | AI 基于事实提出的市场或销售建议 | 经审核后使用 |
| 待补充 | 目前没有足够信息 | 否 |
| 已失效 | 过期、被替代或不再适用 | 否 |

### 1.3 一条知识必须指向判断或动作

知识卡片不只陈述“是什么”，还应尽量包含：

- 适用条件；
- 证据来源；
- 应采取的动作；
- 不可承诺的红线；
- 仍需确认的未知项。

### 1.4 企业隔离、内外分层

每个出口企业建立独立空间，不能跨企业混用产品、报价、客户、案例或话术。企业内部再区分：

- `Public`：官网、产品公开参数、公开认证、公开案例；
- `Internal`：内部 SOP、成本逻辑、客户分级、谈判边界；
- `Restricted`：底价、毛利、关键客户、付款例外、质量事故和合同风险。

### 1.5 面向人和 AI 双重可用

业务员要能快速阅读、复制和执行；AI 要能准确检索、判断适用条件并引用来源。因此知识库不应只保存大而全的长文档，还要拆成结构化知识卡片。

### 1.6 同一知识，多岗位视图

目录结构是数据组织方式，不应强迫所有人按目录学习。系统应根据角色和场景动态组装页面，例如新人只看到“今天要记住什么”，销售只看到“本商机下一步做什么”，管理层看到“哪些红线和缺口正在影响成交”。视图引用同一知识卡，不复制出多个容易冲突的版本。

### 1.7 背调最小必要与合规使用

客户背调只收集与企业真实性、业务匹配、采购判断、沟通时机和风险控制有关的合法公开信息。不得绕过登录、权限或平台限制；不得把私人生活信息、敏感个人信息或未经证实的负面信息用于施压。对客沟通只自然引用业务相关公开事实，不能用“我把你查得很清楚”的方式制造不适。

### 2.3 业务速查卡的固定结构

每家企业自动生成一张可打印或固定在工作台首页的速查卡：

- 一句话定位与3–5个可信优势；
- 3–8个主推产品及各自适合的买家；
- 3–6类核心买家及第一切入点；
- 询盘必问5–10项；
- 全年采购/生产/出货节奏；
- 价格、付款、认证、免费样、独家、索赔和账号变更红线；
- 当前证书、目录、报价和案例的入口；
- 需要主管立即介入的升级信号。

### 2.4 知识中台交互标准

如果以网页或桌面端呈现，至少支持：全局搜索、按岗位/产品/市场/买家/阶段筛选、来源与更新时间徽标、一键复制批准话术、折叠FAQ、最近使用、待确认、待审批、过期预警、学习进度和反馈纠错。搜索结果先显示“最短答案 + 适用条件 + 来源 + 下一步”，再允许展开完整内容。

## 3. 二十一个标准模块

### 00. 知识库总索引与治理

**目的**：告诉人和 AI“知识在哪里、哪些已确认、哪些不能用”。

**主要内容**：

- 企业知识地图与模块导航；
- 当前知识库成熟度；
- 高优先级缺失项；
- 过期内容与更新提醒；
- 负责人、审核人和版本记录；
- 禁止对外使用的内容清单。

**工作台输出**：业务速查卡、新人7天路径、岗位待办、最近更新、即将过期证书、待主管审批、客户沉默预警。

**新人7天路径建议**：

1. Day 1：公司定位、核心信任点和红线；
2. Day 2：主推产品、参数和快速选型；
3. Day 3：ICP、买家角色与全年采购节奏；
4. Day 4：询盘识别、必问问题和客户背调；
5. Day 5：报价、样品、定制和付款单证；
6. Day 6：异议、沉默诊断、挽回和升级信号；
7. Day 7：模拟询盘并完成一次从背调到下一步动作的实战验收。

**核心方法**：专家人设法、信号—动作映射法。

### 01. 来源、证据、权限与口径

**目的**：确保每个结论可追溯，不把推测当事实。

**主要内容**：来源 URL/文件、采集时间、证据等级、语言、适用市场、有效期、敏感级别、企业确认状态；公司名、品牌名、产品名、行业词、规格单位和认证简称的统一口径。

**必须输出**：

- 来源登记表；
- 证书及有效期表；
- 中英文术语与同义词表；
- 产品名称标准化表；
- 冲突信息处理记录。

**行业与业务术语词典字段**：中文术语、标准英文、简明解释、适用产品/工艺/市场、询盘中如何使用、对客标准话术、常见误用、证据或负责人。词典应覆盖产品、材料、工艺、质量、认证、定制、贸易条款、单证、付款、平台运营和客户类型。

### 02. 企业身份与可信实力

**回答**：企业是谁，为什么值得信任？

**字段**：

- 法定或公开公司名称、品牌名、成立时间、所在地；
- 工厂/贸易/工贸一体属性；
- 核心业务、主要产品、经营市场；
- 工厂面积、员工、产线、产能等公开信息；
- OEM/ODM/研发/模具/打样能力；
- 认证、审核、专利、奖项；
- 公开客户、合作品牌和案例；
- 可证明的核心优势；
- 公司简介多版本：30字、100字、300字、中英文；
- 待确认项与禁止夸大项。

**核心方法**：对象画像法、多版本话术法、决策漏斗排序法。

### 03. 品牌与对外信息口径

**回答**：企业以什么身份和语言对外表达？

**字段**：品牌定位、价值主张、品牌故事、品牌语气、视觉资产、Logo 使用、标准颜色、核心口号、关键英文表达、禁用表达、不同市场的本地化口径。

**输出版本**：官网版、展会版、LinkedIn 版、邮件签名版、平台店铺版、政府或协会介绍版。

### 04. 产品知识与产品图谱

**回答**：卖什么、适合谁、在什么条件下卖？

每个产品或产品系列必须建立独立知识卡，至少包括：

| 字段组 | 必备字段 |
|---|---|
| 身份 | 产品 ID、标准中英文名、别名、类别、系列、型号 |
| 属性 | 材料、规格、尺寸、颜色、性能、包装、可选配置 |
| 场景 | 使用场景、终端用户、适用渠道、适用市场 |
| 价值 | 核心卖点、解决的问题、可证明的差异点 |
| 商务 | MOQ、样品、价格影响变量、交期、付款、贸易条款 |
| 定制 | Logo、颜色、包装、结构、配方、模具、认证支持 |
| 合规 | 适用标准、认证、测试报告、限制市场 |
| 销售 | 适合的买家、关联产品、替代品、交叉销售、常见异议 |
| 证据 | 来源页面、目录、图纸、测试报告、照片、确认人 |
| 边界 | 不支持项、不可承诺项、待确认字段 |

产品线同时按“引流款、成交款、定制款”分层，并按市场与买家类型建立快速选型表。

产品还应按业务状态分为：

- **现有已验证产品**：可提供规格、样品、报价或订单证据；
- **能力延伸产品**：基于现有材料、工艺或模具可开发，但尚未成为稳定SKU；
- **机会产品**：根据买家需求、市场空白和询盘数据提出的新品建议；
- **暂停/淘汰产品**：合规、质量、利润、交期或战略上不再推荐。

机会产品必须进入独立机会池，不得混入“现有产品”冒充企业能力。机会池至少包含：目标买家、需求证据、与现有能力的协同、核心参数、合规要求、开发难度、预计投入、验证动作、优先级P0–P3和负责人。

**核心方法**：数据表分组法、产品三结构法、变量—影响法。

### 05. 制造、研发、质量与供应能力

**回答**：企业是否能稳定做出来、按时交付并处理异常？

**字段**：工艺流程、设备、产线、模具和研发、原料管控、质量节点、检验标准、AQL（如适用）、追溯机制、产能、旺季限制、外协环节、异常处理、持续改进、保密与知识产权保护。

**禁止自动认定**：真实月产能、良率、客诉率、关键外协比例。官网未明确时一律标为待确认。

### 06. 认证、法规与市场准入

**回答**：产品在哪些市场能卖，需要什么证明？

**字段**：证书名称、证书编号、发证机构、覆盖产品、适用市场、有效期、文件位置、是否公开、是否需客户自行认证、法规变化风险。

**输出**：

- 产品 × 市场 × 认证矩阵；
- 证书到期预警；
- 对客合规话术；
- 不得宣称的认证或性能；
- “已有 / 可配合 / 尚未具备”三种状态。

> 合规模块只用于信息组织和提醒，不能替代律师、认证机构或当地监管部门的正式意见。

### 07. 商务政策、报价与交付规则

**回答**：在什么商务条件下可以成交？

**字段**：

- MOQ 与阶梯逻辑；
- 样品费、模具费、打样周期；
- 价格币种、税费、有效期；
- 影响报价的变量及计算逻辑；
- EXW/FOB/CIF/DDP 等适用边界；
- 付款方式、账期和例外审批；
- 生产交期、旺季和加急规则；
- 包装、唛头、装柜、物流、保险；
- 质保、索赔、退换和售后；
- 底价、毛利、免费项、赔付和账期红线。

**单证与收款安全子库**：PI、CI、PL、B/L、CO、保险和检验文件的用途、字段、版本、责任人和核对规则；EXW/FOB/CIF/DDP等条款的责任边界；定金、尾款、放单、电放和账期审批；收款账号变更必须通过电话/视频/多渠道复核，任何业务员不得仅凭邮件更改。

每个订单节点都要留下：客户确认、内部确认、版本号、责任人、时间戳和对应附件。样品编号、颜色/材料版本、Logo位置、包装版本与确认照片必须可在复购时直接调取。

**核心方法**：变量—影响法、流程阶段法、异议—回应法。

### 08. 目标市场与行业情报

**回答**：优先做哪些国家、渠道和应用场景？

**字段**：目标国家/区域、市场规模或需求信号、主要渠道、价格带、季节性、当地法规、包装偏好、采购周期、竞争强度、进入难度、推荐产品、风险与验证计划。

该模块首先生成“行业入门卡”：行业定位、需求为什么存在、价值链、常见产品结构、核心工艺、质量风险、合规主题、主要买家、价格与交期驱动。然后生成“供应商视角年度节奏表”，明确客户零售旺季、采购立项、签样、下单、生产、装船和复购回访之间的提前量，避免把客户销售旺季误认为我方接单旺季。

**输出**：市场优先级评分，不把“全球市场”当成有效市场定位。

建议评分维度：需求匹配 25%、合规可达 20%、利润潜力 20%、竞争强度 15%、交付适配 10%、现有证据 10%。企业可按行业调整权重。

### 09. ICP 与买家决策委员会

**回答**：最值得开发的公司和人是谁？

每类 ICP 至少包括：

- 目标国家、渠道和公司类型；
- 公司规模、品牌阶段和供应链模式；
- 典型产品组合与采购量级；
- 可观察识别信号；
- 采购动机、痛点与成功标准；
- 采购、Sourcing、产品、供应链、质量、老板等角色；
- 每个角色的关注点、权力和信息需求；
- 主推产品与切入价值；
- 决策周期、复购潜力和服务成本；
- 常见顾虑、差异化回应；
- A+/A/B/C 评级与对应投入。

**核心方法**：对象画像法、分层投入法、矩阵交叉法。

### 10. 买家意图信号与机会评分

**回答**：看到什么信号，应当做什么动作？

信号类型包括：

- **交易信号**：近月持续进口、供应商变化、采购频率上升、品类扩张；
- **公司信号**：融资、扩店、新市场、新品发布、招聘采购或供应链岗位；
- **网站信号**：新增品类、缺货、交期差评、认证诉求、可持续承诺；
- **社媒信号**：产品发布、展会、合作、客户投诉、采购负责人变动；
- **互动信号**：打开邮件、下载目录、回复、索样、询价、查看资质；
- **风险信号**：公司状态异常、付款风险、长期无回复、需求与能力不匹配。

每个信号必须映射：信号来源 → 可信度 → 机会阶段 → 推荐动作 → 时限 → 升级条件。

建议机会评分：ICP 匹配 30%、真实采购证据 25%、时间性 15%、联系人权力 10%、产品匹配 10%、互动强度 10%。

### 11. 竞争对手与差异化

**回答**：客户为什么选择我们，而不是替代供应商？

**字段**：竞对类型、地区、产品、价格定位、认证、渠道、优势、弱点、客户为何选择其、我方可证实差异、不可攻击事项、竞品替换切入点。

差异化必须形成“客户问题 → 我方能力 → 证据 → 商业结果”的证据链，不允许只写“质量好、服务好、价格有竞争力”。

建立“痛点—证据—切入”映射表：从官网条款、保修政策、社媒评价、召回/投诉、贸易变化和客户原话中发现问题；再映射到我方可提供的产品、质量、包装、交期、合规或服务证据。若只有问题、没有我方可证实能力，则只能记录为情报，不能写进开发信。

### 12. 产品—市场—买家匹配

**回答**：哪个产品优先推给哪个市场中的哪类买家？

核心矩阵：

```text
产品/系列 × 国家/区域 × 渠道 × 买家类型 × 使用场景
→ 推荐等级 × 卖点 × 证据 × 风险 × 首次切入动作
```

此模块是产品知识、ICP、市场与销售动作之间的中枢，必须避免“有产品无对象”或“有客户无对应方案”。

### 13. 线索发现与客户背调

**回答**：去哪里找客户，找到后怎样判断真假和价值？

**渠道**：海关或贸易数据、Google、行业目录、展会、LinkedIn、品牌官网、经销商名录、B2B 平台、协会、招聘、社媒与新闻。

**标准流程**：

1. 从产品图谱生成关键词、同义词、用途词、买家类型词和候选 HS 编码；
2. 找到候选公司；
3. 验证官网、业务模式、产品匹配和经营状态；
4. 识别采购委员会；
5. 收集合法公开的联系入口；
6. 记录证据，去重并评分；
7. 输出第一触达策略。

**客户背调卡**：公司事实、产品与渠道、采购证据、供应商情况、关键人物、痛点信号、风险、评分、推荐产品、切入点、下一步动作。

**背调采用三级投入**：

| 层级 | 建议时长 | 目标 | 适用对象 | 主要输出 |
|---|---:|---|---|---|
| L1 快速验真 | 5分钟 | 判断公司是否真实、需求是否匹配、是否存在诈骗/骗样风险 | 所有新线索与询盘 | Go / Hold / No-go、风险提示 |
| L2 价值评估 | 20–30分钟 | 判断客户类型、渠道、规模、产品匹配、联系人和切入点 | 有基本信息的目标客户 | A+/A/B/C评级、首推产品、触达角度 |
| L3 深度背调 | 重点客户专用 | 判断采购周期、供应商结构、决策委员会、真实卡点和推进策略 | 高价值、明确需求或谈判客户 | 证据包、账户策略、报价/样品/跟进计划 |

**背调来源地图**：

- 官网：About、Products/Brands、Terms/PO Terms、Privacy、FAQ/Warranty、News；
- 地图：地址真实性、办公/仓库/门店形态、营业时间和联系信息一致性；
- 贸易数据：品类词云、进口趋势、供应商区域、最近采购和采购周期；
- LinkedIn/Facebook等官方社媒：公司动态、在售产品、招聘、展会、关键岗位；
- 搜索与第三方：公司注册、召回、评价、PDF、行业目录、历史官网；
- 客户互动：询盘、邮件、会议、样品、报价和订单记录。

所有推断必须与客户对话互相验证。贸易数据、社媒动态和历史网页只能作为线索，不能自动视为当前采购事实。

**背调完成标准**：不仅找到邮箱，还要回答“是不是目标客户、值不值得投入、联系谁、用什么产品和证据切入、何时触达、下一步是什么”。

### 14. 客户资产、老客户与关系生命周期

**回答**：在数万或数十万客户中，谁最值得现在跟进，为什么，由谁在什么时候做什么？

该模块不是通讯录，也不是静态客户标签。它把客户公司、联系人、商机、互动、订单、产品兴趣、采购周期、风险和下一步动作连成“客户关系知识图谱”，是老客户复购、沉睡唤醒、交叉销售和销售管理的核心。

#### 14.1 客户知识的八类核心实体

| 实体 | 说明 | 关键关联 |
|---|---|---|
| Account 客户公司 | 一个真实买家组织的黄金主记录 | 联系人、商机、订单、贸易数据、风险 |
| Contact 联系人 | 采购委员会中的个人及其职位、权力和触达状态 | 所属公司、互动、商机角色、许可状态 |
| Opportunity 商机 | 一次明确采购机会及其阶段、金额、概率和时间 | 产品、联系人、报价、样品、任务 |
| Interaction 互动 | 邮件、平台消息、WhatsApp、会议、点击、下载、网站行为 | 联系人、商机、信号强度和时间 |
| Transaction 交易 | 历史报价、样品、订单、回款、毛利、售后与复购 | 客户、产品、批次、采购周期 |
| Product Interest 产品兴趣 | 客户关注、询盘、采购或可能交叉销售的产品 | 产品ID、证据、数量、市场、匹配度 |
| Task/Next Action 任务 | 下一步动作、负责人、截止时间和完成证据 | 客户、联系人、商机、SLA |
| Risk/Consent 风险与许可 | 欠款、投诉、退订、退信、黑名单、隐私与营销许可 | 控制评分、触达和自动化 |

必须区分 `Account` 和 `Contact`：同一客户公司可以有多个采购、产品、质量、财务和管理层联系人；联系人离职不等于客户流失。一个客户可以有多个产品和多个并行商机，不能用最后一封邮件覆盖全部历史。

#### 14.2 黄金主记录与9万客户清洗

客户入库前先建立去重与合并规则：标准化公司名、官网域名、邮箱域名、国家/地址、电话、税号或注册号；识别母子公司、品牌与法人、分公司和门店。合并记录时保留所有来源、原负责人、互动、订单和审计日志，不得因自动去重丢失历史。

每条客户主记录至少包括：

- Account ID、标准公司名、品牌、域名、国家、语言、时区；
- 客户类型、渠道、规模、目标市场和ICP匹配；
- 联系人及采购委员会完整度；
- 关注产品、历史询盘、报价、样品、订单和售后；
- 最近有效互动、当前商机阶段、下一步任务与负责人；
- 历史采购周期、预计复购窗口和季节节点；
- 海关/贸易采购证据及供应链变化；
- 累计收入、订单次数、毛利、回款和服务成本；
- 退订、退信、投诉、欠款、争议、黑名单与营销许可；
- 当前评分、分层、评分原因、有效期和更新时间。

#### 14.3 客户动态优先级

概念公式：

> 客户优先级 = 当前采购意向 × 产品匹配度 × 采购实力 × 成交进度 × 可触达性 − 风险

乘法用于表达“任何关键环节接近零都会显著降低优先级”；系统实际落地建议采用可解释的100分加权模型，并设置硬性停止条件。

| 评分模块 | 分值 | 主要依据 |
|---|---:|---|
| 当前采购意向 | 25 | 新询盘、明确回复、RFQ、询价、索要样品/交期/认证/付款条件 |
| 产品与ICP匹配 | 20 | 产品、国家、渠道、MOQ、价格带、认证和应用场景 |
| 采购实力与周期 | 20 | 历史成交、贸易采购、采购频率、数量、复购窗口、供应商结构 |
| 商机推进程度 | 15 | 已报价、样品、测试、谈判、合同、付款 |
| 历史客户价值 | 10 | 成交金额、次数、毛利、回款、复购、服务成本 |
| 联系与互动质量 | 10 | 是否决策人、邮箱/WhatsApp/LinkedIn有效、回复、点击、下载 |
| 风险扣分 | 0至-100 | 欠款、严重纠纷、退订、黑名单、持续退信、产品不匹配 |

**参考加分**：7天内明确回复 +10；索要报价/样品/交期 +8；已报价或寄样 +8；近90天有匹配采购证据 +8；接近历史复购时间 +6；邮件点击或附件下载 +4；找到采购决策人 +5；近期登录只能 +1～2。

**风险与停止条件**：退订、黑名单或明确拒绝营销应停止营销自动化；持续退信建议 -20 并进入数据修复；欠款或严重纠纷建议 -30 并暂停常规促销；产品明显不匹配 -20；连续多次无回应按客户价值和周期衰减，不机械永久扣分。

评分权重、阈值、时间窗口和加减分必须由企业确认并版本化。模型每月用实际赢单、复购和回款校准，不能把AI“高价值客户”标签当作唯一结论。

#### 14.4 信号强弱与时间衰减

| 信号等级 | 示例 | 默认处理 |
|---|---|---|
| 强信号 | 明确回复、索要报价/MOQ/样品/交期/认证/付款；报价、寄样、测试、谈判；临近复购 | 进入人工优先队列 |
| 中强信号 | 匹配RFQ、近月真实采购、供应商变化、重复访问同一产品、下载关键附件、多次点击 | 与匹配度/能力/时机叠加后升级 |
| 弱信号 | 近期登录、单次打开邮件、浏览公司主页 | 只作辅助，不单独进入S/A级 |
| 负向信号 | 退订、退信、投诉、欠款、明显不匹配、只比价无计划 | 降级、暂停或停止营销 |

重点客户至少满足以下四类中的两类：有行动、有匹配、有能力、有时机。例外是历史高价值且已经进入复购窗口的老客户，即使近期没有登录，也应优先跟进。

所有行为信号都应记录发生时间、来源和有效期。登录、打开等弱信号衰减快；成交历史、复购规律和真实采购能力衰减慢。不同产品的采购周期不同，不能用统一“30天未动”判断所有客户沉睡。

#### 14.5 S/A/B/C/D动态分层

| 层级 | 参考定义 | 9万客户示例 | 主要运营方式 |
|---|---|---:|---|
| S 黄金商机 | 高分且有强采购/复购信号，无硬风险 | 300–500 | 当天人工跟进，主管每日检查 |
| A 重点客户 | 高匹配、有能力或正在推进 | 1,000–2,000 | 1个工作日内个性化跟进 |
| B 培育客户 | 有潜力但时机、联系人或需求未成熟 | 5,000–10,000 | 自动培育，出现强信号后升级 |
| C 沉睡客户 | 历史询盘/成交但长期无有效互动 | 约20,000 | 按产品、国家和采购季节分批唤醒 |
| D 低价值/无效 | 低匹配、无效、重复、不可触达或停止营销 | 其余 | 清洗、归档、公海或停止营销 |

上述数量只是9万客户场景的运营参考，不能代替评分阈值和团队容量。每位业务长期持有的人工重点池建议控制在：S级20–30家、A级100–150家、B级300–500家；其余由自动化培育和异常信号触发。禁止把9万客户平均分给业务员。

#### 14.6 老客户专属生命周期

老客户至少区分：活跃复购、复购将至、增长扩品、成交下降、服务风险、联系人流失、沉睡可唤醒、流失确认。每种状态绑定产品、最近订单、平均采购间隔、下一预计窗口、最近联系人、历史毛利、未解决售后和“下一最佳动作”。

优先识别：

- 历史成交两次以上且临近平均复购周期；
- 采购量或产品范围增长，可交叉销售；
- 采购频率下降、供应商变化或长期未联系；
- 过去沉睡但重新回复、点击、访问或产生采购记录；
- 原联系人失效但公司仍有采购能力；
- 有投诉、欠款或交付问题，必须先解决关系风险再营销。

#### 14.7 八个动态客户名单

1. **今日必须跟进**：7天内新询盘/主动回复/索要报价，产品匹配，24小时无有效跟进；
2. **报价后未推进**：已报价3–14天，仍有互动或产品行为，无下一步任务；
3. **样品未转订单**：样品预计到货/测试时间已到，尚无反馈或订单；
4. **老客户复购预警**：历史成交两次以上，接近平均采购周期，30天无业务联系；
5. **高互动但未询盘**：7天内多次点击、下载或查看产品，ICP匹配，尚未正式询价；
6. **采购异动客户**：近90天有匹配采购，采购量增长、供应商减少或更换，尚未成交或已沉睡；
7. **沉睡后重新活跃**：过去询盘/成交过，180天以上无沟通，近期重新互动或产生采购证据；
8. **高分但漏跟进**：评分达到企业设定阈值（参考65分），7天无跟进、无下一行动，商机仍在询价至谈判阶段。

所有动态名单必须每日或按事件重算，记录入选原因、负责人、SLA、推荐话术和退出条件，避免客户永久贴标签。

#### 14.8 CRM/OKKI字段与平台边界

客户知识库采用平台无关的数据模型。OKKI、其他CRM、国际站、邮箱、WhatsApp、LinkedIn和海关数据只是数据源或执行入口；不同产品版本可见字段可能不同。可直接读取的字段建立映射，缺失维度通过自定义字段、标签或外部计算补充。

每个字段必须登记：标准字段名、平台字段名、实体类型、数据来源、更新方式、允许值、负责人、敏感级别、评分用途和冲突处理。CRM默认排序或AI高价值识别只能作为辅助信号，最终优先级还要叠加企业自己的产品匹配、采购周期、利润、回款和风险规则。

#### 14.9 下一最佳动作与验收指标

每个S/A客户必须具备：当前判断、支持证据、推荐产品、核心卡点、推荐联系人、下一动作、负责人、截止时间、建议话术和完成结果。禁止用“继续跟进”作为有效下一步。

客户资产库重点指标包括：黄金主记录覆盖率、重复率、有效联系人率、决策人覆盖率、S/A客户有下一步比例、逾期任务数、报价/样品漏跟进率、复购预警命中率、各层转化率、沉睡唤醒率、退订/投诉率、收入与毛利、评分预测与实际结果偏差。

### 15. 询盘识别、资格判断与推进

**回答**：这是不是值得投入的商机，下一步问什么？

**字段**：询盘来源、客户身份、需求产品、规格、数量、用途、市场、认证、预算、时间、决策链、现有供应商、真实动机、风险、机会评分、下一步动作。

**询盘10步速检**：国家/渠道 → 产品 → 定制深度 → 参数 → 数量/MOQ → 包装 → 合规/测试 → 目标交期 → 目的港/贸易条款 → 单一下一步。首次沟通只追问当前最关键的2–3项，避免一次抛出长问卷。

**提问采用三层下钻**：

- L1 事实：产品、数量、市场、交期是什么；
- L2 影响：现有问题造成什么成本或风险；
- L3 动因：为什么现在要解决、怎样算成功。

**必须输出**：24小时内动作、需要客户补充的信息、我方需内部确认的信息、下一封话术、升级红线。

**资格结果**：`Go`立即投入、`Nurture`等待采购窗口、`Hold`等待关键信息、`No-go`不匹配或高风险。评级必须附依据与下一次复核时间。

### 16. 方案、选型、报价与样品

**回答**：怎样把需求转成合适方案，而不是只报一个价格？

**流程**：需求确认 → 产品匹配 → 差异说明 → 规格确认 → 报价变量 → 阶梯方案 → 样品方案 → 交期与风险 → 下一步承诺。

**输出模板**：

- Good / Better / Best 三档方案；
- 标准品 / 改款 / 全定制三类方案；
- 报价单字段标准；
- 样品转订单计划；
- 报价有效期与假设条件；
- 客户未提供完整信息时的条件报价规则。

**定制深度标准**：标准现有款 → 轻定制（Logo/颜色/标签/包装）→ 改款ODM → 全新开模 → 多SKU套装。每级绑定必需资料、MOQ逻辑、样品/模具费、开发周期、签样点、知识产权、质量风险和审批人。

**样品档案**：每个样品建立唯一编号，保存规格、材料/釉色或色号、容量/尺寸、Logo文件与位置、包装版本、照片、快递、客户反馈、修改轮次、签样状态和对应大货批次。未经书面签样，不进入定制大货。

### 17. 异议、谈判、风险与审批

**回答**：客户卡住时怎样判断真实原因并守住边界？

高频主题：价格高、MOQ 高、交期长、缺少认证、先赊账、免费样品、独家、模具归属、质量担忧、已有供应商、暂不回复。

每条异议按以下格式保存：

```text
客户原话 → 表面问题 → 需澄清的问题 → 真实卡点假设
→ 回应策略 → 中英文话术 → 可交换条件 → 绝对红线 → 升级人
```

异议至少按价格、MOQ、样品费、交期、已有供应商、历史质量问题、大货与样品一致性、模具费、证书缺失、独家/排他十类建设，并给出轻/中/强三级强度、快速回应、下一步和升级条件。

**强制升级信号**：低于授权底价、账期/赊销、免费开模、独家/排他、第三方验货或工厂审计、索赔/赔偿、收款账号变更、公司暂无但客户要求的证书。AI 只能生成“需要内部确认”的回复，不能代替主管批准。

**核心方法**：异议—回应法、穿透式语义分析法、信号—动作映射法。

### 18. 销售内容与多触点话术

**回答**：不同对象、阶段和渠道该说什么？

**内容类型**：公司介绍、开发邮件、LinkedIn 邀请与 InMail、WhatsApp、询盘回复、跟进、报价说明、样品催进、展会邀请、节日问候、唤醒、分手信、成交后复购、社媒内容。

每份内容至少标注：适用 ICP、产品、渠道、阶段、语言、长度、个性化字段、证据引用、禁用承诺、CTA。

禁止把同一封通用开发信发给所有市场。优先生成“买家信号 + 具体产品 + 可验证价值 + 单一下一步”的个性化版本。

**渠道运营子库**：

- B2B平台：标题公式、核心词/长尾词、属性、详情页、图片Alt、FAQ、询盘来源复盘；
- 独立站：首页、品类页、产品页、定制页、证据/合规页、案例页、询盘页；
- SEO/GEO：搜索意图、主题集群、买家指南、选型/对比、结构化FAQ和证据引用；
- 社媒：品牌语气、内容支柱、产品场景、案例、展会和市场本地化；
- 广告：关键词、落地页、转化事件、否定词和合规声明；
- 多语言FAQ：按信任→产品→定制→质量合规→商务物流→复购的决策顺序组织。

平台和独立站内容只能调用“可公开、证据已核验”的知识；内部底价、客户隐私和Restricted内容不得进入外部内容生成。

### 19. 订单、交付与售后

**回答**：成交后怎样避免错误并促进复购？

**流程节点**：合同确认、PI、付款、打样、产前样、物料、生产、检验、包装、订舱、报关、单证、到港、验收、售后、复购。

每个节点记录：必须确认项、责任人、文件、时间、风险信号、预防动作、异常升级、客户沟通口径。

**售后分级建议**：

| 等级 | 示例 | 响应目标 | 处理要求 |
|---|---|---:|---|
| P1 严重 | 大批量质量/安全问题、客户停售、重大交期或货权风险 | 立即登记，24小时内初步响应 | 管理层、品质、业务、法务/保险等联合处理 |
| P2 重要 | Logo、包装、明显色差、局部破损或数量争议 | 48小时内初步判断 | 对照签样、PI、QC、装箱和收货证据 |
| P3 一般 | 轻微瑕疵、使用咨询、可解释工艺差异 | 72小时内处理 | 标准话术、记录并观察是否形成高频问题 |

售后证据包应包含订单号、产品与批次、样品编号、外箱与内包装照片、问题近图/视频、数量、到货时间、QC记录、出货照片和客户诉求。任何赔付、折扣、补发或抵扣方案必须按权限书面审批。

### 20. 复盘、指标与持续学习

**回答**：哪些知识有效，哪里导致赢单或输单？

**回流内容**：

- 新询盘问题 → FAQ、产品或 ICP；
- 高频异议 → 谈判库和官网内容；
- 赢单原因 → 差异化与成功案例；
- 输单原因 → 产品、价格、交期、认证或业务动作；
- 交付异常 → SOP、红线和预警；
- 新证书/新品/产能变化 → 企业真相层；
- 市场和法规变化 → 市场与合规模块。

**沉默诊断与客户挽回**：

- 报价后沉默：优先判断价格、配置、决策权、运费条款或项目暂停；
- 看款后沉默：缩小到3–5款，按渠道说明推荐理由；
- 寄样后沉默：具体询问尺寸、手感、颜色、功能、Logo和包装反馈；
- 长期沉默：判断采购窗口、联系人变化、项目状态和客户价值。

只挽回产品匹配、卡点可解决、有明确采购窗口或曾有实质互动的客户。低匹配、纯比价、骗样、骗设计、钓鱼或长期无企业信息的客户进入低频维护或停止投入。每次挽回必须带新价值、新证据、新方案或明确问题，禁止连续发送“Any update?”。

**案例与周报资产**：案例按客户背景、痛点、方案、证据、结果、可复用话术和适用边界记录；没有真实结果的内容必须标为“训练模板”，不得作为成功案例对外使用。周报至少复盘新增/重点客户、画像分布、高频产品、报价与样品、卡点、沉默原因、知识缺口、下周动作和需主管支持事项。

**复盘采用四维归因**：客户、业务、产品、运营；并定位询盘 → 报价 → 样品 → 订单 → 复购漏斗中的主要断层。

## 4. 仅凭“公司简介 + 官网”的自动构建流程

### 步骤 1：建立企业身份

解析公司中英文名、品牌名、域名、国家/地区、业务类型和主营产品。若公司名称与网站信息冲突，暂停生成对外口径并列入高优先级确认。

### 步骤 2：采集官网与公开资产

优先读取：

1. 首页、About、Products/Categories；
2. Manufacturing/Factory、Quality、R&D、OEM/ODM；
3. Certificates/Compliance、Downloads、Catalog；
4. Applications/Industries、Cases/Projects；
5. FAQ、Shipping、Payment、Warranty；
6. News/Blog/Exhibition；
7. Contact、Privacy、Terms；
8. sitemap、公开 PDF、产品图和证书图。

在企业官网身份确认无误后，可补充发现其官方 B2B 平台店铺、LinkedIn/社媒、展会页、行业目录和公开新闻；这些来源必须单独标注，不能覆盖企业官网或正式文件。平台价格、评分、响应时间、供应能力、认证和交易数据具有强时效性，必须记录抓取日期并等待企业确认后再用于对客表达。

如官网为 JavaScript 渲染或存在抓取限制，应使用可见浏览器读取公开页面；仍不可读取时，记录缺口，不反复重试或绕过权限。

### 步骤 3：清洗和标准化

- 合并重复页面与重复产品；
- 统一公司名、品牌名、规格、币种和计量单位；
- 建立中英文产品同义词；
- 建立行业、工艺、质量、贸易和平台运营术语词典；
- 区分产品系列、单品、配件和应用；
- 区分“现有产品、能力延伸、机会产品、暂停产品”；
- 对候选 HS 编码只作“检索线索”，未经报关或专业确认不得作为正式归类；
- 识别过期证书、矛盾参数和不一致的 MOQ/交期。

### 步骤 4：识别行业并加载行业分支

AI 根据产品、材料、应用和认证识别行业，选择通用模块之外的行业增强字段，见第 9 章。无法确定时允许多标签，不强行单选。

### 步骤 5：生成企业真相层

先生成公司、品牌、产品、制造、质量、认证和公开商务信息。所有结论携带来源；没有来源的内容不能写成事实。

### 步骤 6：生成市场决策层草稿

根据产品用途、公开出口市场、认证覆盖、客户案例和行业常识，生成行业入门卡、供应商视角年度节奏、初步市场、ICP、意图信号、竞对类型和产品—市场匹配。该层默认标记为“建议策略”或“AI 推断”，等待企业确认。

### 步骤 7：生成销售执行层草稿

形成速查卡、新人路径、L1–L3客户背调、询盘提问表、产品选型、定制与样品档案、报价变量、异议与升级库、沉默诊断、挽回话术、平台发品/SEO、双语FAQ、交付与售后流程。涉及价格、MOQ、付款、产能、交期、认证承诺和赔付的内容只生成待确认字段，不能代替企业做承诺。

### 步骤 8：输出分批确认队列

不一次抛出几十个问题。按对成交的影响分三批：

- **第一批：立即影响获客**——主推产品、目标市场、理想客户、核心差异；
- **第二批：立即影响报价**——MOQ、价格变量、样品、交期、定制、认证；
- **第三批：影响风险和规模化**——付款红线、产能、售后、赔付、案例公开权限。

### 步骤 9：验证、发布与测试

企业确认后更新状态，执行冲突检查、敏感信息检查和对客话术检查。再按六种岗位视图发布，并用不少于30个典型业务问题做检索测试，确保 AI 能给出正确答案、来源、适用条件和下一步动作。

测试题应覆盖：公司与信任、产品选型、买家匹配、客户背调、询盘分级、报价条件、样品/定制、认证边界、异议升级、单证付款、交付售后、沉默挽回。至少设置5个“知识库应拒绝猜测或要求人工确认”的反例。

### 步骤 10：持续更新

官网、目录、认证、CRM、邮件、询盘、报价、订单和售后产生变化时，触发相应模块更新；旧内容保留版本但退出有效检索范围。

### 4.1 两阶段建库边界

**阶段A：企业知识冷启动**只需要公司简介和官网，可生成企业、产品、市场、ICP、销售流程、客户评分规则和空白客户卡模板，但不能凭空生成真实客户、成交和复购信息。

**阶段B：客户资产建库**必须接入或导入OKKI/CRM、国际站客户、邮箱互动、商机、报价、样品、订单、回款和售后数据。建议按以下顺序执行：

1. 盘点数据源、字段、时间范围、负责人和权限；
2. 备份原始数据，建立Account与Contact黄金主记录并去重；
3. 统一产品ID、客户ID、商机阶段、互动类型和订单口径；
4. 计算历史采购周期、最近有效互动、商机停留时间和可触达状态；
5. 企业确认评分权重、硬停止条件、分层阈值和各层容量；
6. 先用一批已知赢单、流失、复购和无效客户校准评分；
7. 生成S/A/B/C/D分层和八类动态名单；
8. 给S/A客户补齐决策人、下一动作、负责人和截止日期；
9. 自动化培育B/C客户，但先排除退订、黑名单、欠款争议和不可营销对象；
10. 每月根据转化、复购、回款和投诉校准规则，不断修正模型偏差。

> 企业知识库解决“应该怎么卖”，客户资产库解决“此刻该卖给谁”。两者缺一不可。

## 6. 统一知识卡片与元数据标准

### 6.1 通用知识卡结构

### 6.3 RAG 拆分标准

- 一张卡只解决一个对象、一个问题或一个决策；
- 正文建议 300–800 个中文字符，复杂产品可拆为多卡；
- 表格过大时按产品系列、市场或买家类型拆分；
- 关键结论放在卡片开头，不能埋在附件末尾；
- 图片、PDF 和证书必须同时保存可检索文字说明；
- 中英文名、旧名、型号和行业俗称放入同义词字段；
- 报价、认证、法规和交期必须有时间戳；
- 训练案例与真实案例分开，未验证的示例不得被检索为成交证据；
- 检索答案必须优先返回“已验证事实”，其次才是公开事实和建议策略。

## 7. 来源与可信度规则

### 7.1 来源优先级

| 等级 | 来源 | 默认可信度 |
|---|---|---|
| S | 企业负责人确认、正式合同、受控内部制度 | 最高 |
| A | 有效证书、检测报告、正式产品规格书、权威监管来源 | 高 |
| B | 企业官网、官方目录、企业官方社媒 | 中高 |
| C | 可靠行业协会、贸易数据、展会资料、权威媒体 | 中 |
| D | 普通第三方目录、搜索摘要、未经核实转载 | 低 |
| I | AI 推断或行业常识推演 | 不可作为事实 |

### 7.2 冲突处理

1. 不静默覆盖冲突信息；
2. 同时保留来源、抓取时间和冲突字段；
3. 以更新、更权威、更具体的来源优先；
4. 涉及价格、认证、规格、付款、交期和法律责任时，必须人工确认；
5. 未解决冲突的字段不得自动生成对外承诺。

### 7.3 时效建议

| 知识类型 | 建议复核周期 |
|---|---|
| 公司基础事实 | 12个月或官网变化时 |
| 产品参数、包装、MOQ、交期 | 3–6个月或产品变化时 |
| 价格、汇率相关口径 | 每次报价前 |
| 认证与检测报告 | 按有效期，至少每季度检查 |
| 市场、法规与竞对 | 1–3个月 |
| 话术、FAQ、异议 | 每月结合询盘复盘 |
| 客户与商机信息 | 每次互动后 |

## 8. 第一轮企业确认清单

AI 完成第一版后，优先只确认以下 15 项：

1. 当前最希望增长的 3 个产品或系列是什么？
2. 未来 12 个月最优先的国家或区域是什么？
3. 最理想的买家公司类型和渠道是什么？
4. 现有最有说服力的差异化与证据是什么？
5. 哪些官网内容已经过期或不能再对外使用？
6. 各主推产品的标准 MOQ 与可协商边界是什么？
7. 报价主要受哪些变量影响，价格有效期多久？
8. 样品费、模具费及样品转订单政策是什么？
9. 标准、旺季和加急交期分别是什么？
10. 可提供哪些 OEM/ODM 项目，哪些做不了？
11. 现有认证分别覆盖哪些产品和市场？
12. 默认贸易条款、付款方式与不可突破红线是什么？
13. 哪些客户、品牌和案例允许公开？
14. 最常见的 5 个客户异议和 5 个输单原因是什么？
15. 哪些市场、客户类型或订单条件明确不做？

确认方式应支持“确认正确 / 修改 / 暂不确定”，不能强迫企业一次补齐所有字段。

### 8.1 客户资产库首轮确认

接入历史客户数据后，再由销售负责人、财务和管理层确认：

1. Account、Contact、商机、订单和产品的唯一ID及去重口径；
2. 哪些系统行为能读取，哪些需自定义字段或标签；
3. 什么算“有效跟进”，哪些动作只是系统自动触达；
4. 产品匹配、采购实力、毛利、回款和服务成本的权重；
5. S/A/B/C/D评分阈值和每位业务的持有上限；
6. 各产品的合理复购周期、旺季和提前跟进时间；
7. 退订、投诉、欠款、争议和黑名单的硬停止规则；
8. 客户归属、公海、转移、离职交接和多人协作规则；
9. S/A客户的跟进SLA和主管检查频率；
10. 自动培育、人工个性化跟进和必须审批的边界。

## 11. 闭环更新机制

```text
官网/目录/证书变化
        ↓
企业真相层 → 产品市场匹配 → 客户资产与销售执行
     ↑                  ↓               ↓
质量/交付改进 ← 赢单/输单/异议 ← 互动/商机/订单/复购
```

### 11.1 更新触发器

- 官网新增或删除产品；
- 产品规格、包装、MOQ、交期或价格政策变化；
- 证书新增、过期或覆盖范围变化；
- 新市场、新渠道、新展会或新客户类型；
- 连续出现同类询盘、异议、输单或客诉；
- 供应链、产能、付款或交付政策变化；
- 市场法规或平台规则变化；
- 客户出现强意向、采购异动、商机停滞、复购将至或重新活跃；
- 退订、退信、投诉、欠款、联系人离职或营销许可变化；
- 评分模型、分层阈值、客户归属或SLA规则变化；
- 业务员发现 AI 答案错误或不适用。

### 11.2 更新审批

| 内容 | 建议审核人 |
|---|---|
| 公司与品牌口径 | 管理层/品牌负责人 |
| 产品参数与选型 | 产品/研发/业务负责人 |
| 质量与认证 | 品质/合规负责人 |
| MOQ、报价、付款、赔付 | 销售负责人/财务/管理层 |
| 交付流程 | 跟单/生产/物流负责人 |
| 话术与 ICP | 销售与市场负责人 |
| 客户主数据、评分与分层 | 销售运营/销售负责人/数据负责人 |
| 回款、毛利、欠款和信用风险 | 财务/管理层 |
| 退订、隐私和营销许可 | 市场运营/合规负责人 |

## 12. AI 使用与回答规范

知识库中的销售 AI 或助手必须遵守：

1. 先识别企业、产品、市场、买家类型和业务阶段；
2. 优先引用已验证且仍有效的知识；
3. 明确区分事实、推断和建议；
4. 关键商务条件无依据时先询问，不得自行补全；
5. 报价、认证、交期、付款、独家、赔付等承诺必须检查红线；
6. 输出不仅要有答案，还要给下一步动作；
7. 涉及客户对外内容时使用正确语言、语气和品牌口径；
8. 不跨企业检索，不泄露 Restricted 内容；
9. 出现来源冲突、低置信度或过期内容时主动提示；
10. 每次纠错都生成知识更新候选，不直接覆盖已验证事实。
11. 不把某个行业案例中的价格、MOQ、周期、认证、法规限值或季节节点复制到其他企业；
12. 对市场法规、认证要求、平台规则和法律责任等易变化信息，使用带日期的权威来源并要求专业复核；
13. 客户背调只陈述业务相关公开事实，对动机、采购量和卡点使用“可能/待验证”，不得伪装成客户已经确认；
14. 若客户需求做不了，输出“能力边界 + 可行替代 + 一个澄清问题”，不能只用一句拒绝结束商机；
15. 所有对客回复保持单一目标和明确CTA，避免一次发送过多问题、产品或附件。
16. 近期登录、单次打开等弱信号不能单独把客户升级为S/A；
17. 历史高价值且复购将至的老客户不能因近期未登录而自动降为低价值；
18. AI每次客户排序必须说明主要加分、扣分、缺失数据、模型版本和推荐下一步；
19. 退订、黑名单、营销许可和严重风险是硬约束，不得因高分被绕过；
20. 自动化不得替代S/A客户的人工判断，也不得向有争议或欠款客户继续常规促销。

## 15. 建库验收清单

### 结构

- [ ] 00–20 模块已建立，允许无内容但必须显示缺口；
- [ ] 产品、市场、买家、话术和流程之间有明确关联；
- [ ] 没有把所有信息堆在一份长文档中；
- [ ] 中英文名称、型号和同义词已统一。

### 可信度

- [ ] 关键事实有来源和采集日期；
- [ ] AI 推断没有伪装成企业事实；
- [ ] 证书、规格、价格和交期具有时效标记；
- [ ] 冲突和脏数据被显式保留并等待确认。

### 业务可用性

- [ ] 每个主推产品能匹配目标市场和 ICP；
- [ ] 每类 ICP 有识别信号、主推方案、顾虑和动作；
- [ ] 询盘可以被分级并给出 24 小时内动作；
- [ ] 报价、付款、认证、交期和赔付设有红线；
- [ ] 高频沟通内容有中英文多版本话术；
- [ ] 有速查卡、新人路径、行业术语和岗位视图；
- [ ] 客户背调按L1/L2/L3投入，并给Go/Hold/Nurture/No-go结论；
- [ ] 现有产品与机会产品严格分开；
- [ ] Account、Contact、Opportunity、Interaction和Order没有混为一张客户表；
- [ ] 客户去重、合并和黄金主记录保留来源与历史；
- [ ] 每个S/A客户都有评分依据、下一动作、负责人和截止日期；
- [ ] 近期登录等弱信号不会单独生成重点客户；
- [ ] 老客户复购、沉睡重活跃、报价停滞和样品未转单可以动态预警；
- [ ] 退订、黑名单、营销许可和严重风险可以覆盖高分并停止营销；
- [ ] 评分模型有版本、时间衰减和实际转化校准；
- [ ] 有异议强度、强制升级信号、沉默诊断和客户挽回规则；
- [ ] B2B平台、SEO和独立站内容只调用批准公开的知识；
- [ ] 真实案例与训练模板严格分开；
- [ ] 订单和售后能反哺产品、话术与 SOP。

### AI 可用性

- [ ] 每张知识卡有唯一 ID 与企业 ID；
- [ ] 有状态、来源、置信度、权限和适用范围；
- [ ] 能过滤过期、冲突和 Restricted 内容；
- [ ] 用至少 30 个典型问题完成检索与回答测试；
- [ ] AI 能在不确定时说“不确定并请求确认”。
