# 外贸 AI Agent 运营落地模型

本模型把外贸 AI 从“会回答问题”推进到“按边界执行、由人担责、用结果复盘”的运营系统。它复用现有 00–20 模块，不另建一套平行知识库。

> 采用边界：本模型参考了用户提供的 2026 年 8 月外贸数智化培训材料，只吸收可泛化的方法。材料中的企业名称、产品、人员、业绩、效率目标和工具能力均未作为本项目事实，也未复制到模板中。

## 1. 四类执行模式

| 模式 | 适用任务 | AI 责任 | 人的责任 |
|---|---|---|---|
| `ai_draft` | 检索、归纳、背调草稿、内容草稿、报告初稿 | 基于已授权来源产出可审阅结果 | 核验来源、事实、口径与适用范围 |
| `automated` | 已批准规则内的归集、去重、提醒、格式校验、状态同步 | 按确定性规则执行并留下日志 | 配置规则、监控异常、处理失败 |
| `human_in_loop` | 报价、发品、商机评分、质检报告、单证比对 | 给出建议、差异或草稿 | 审批、修改并确认对外或落库结果 |
| `human_led` | 谈判签约、付款放款、账期/底价/独家、赔付、法律合规、人事敏感决定 | 整理证据和备选方案 | 判断、授权、执行并承担责任 |

默认规则：无法证明任务可逆、可审计且已获授权时，至少使用 `human_in_loop`；涉及资金、合同、法律、隐私、用工、重大质量或客户关系时使用 `human_led`。

## 2. 四个运营知识包与现有模块映射

| 运营知识包 | 复用模块 | 解决的问题 |
|---|---|---|
| 产品 | 04、05、06、12 | 产品是什么、适合谁、能否制造、在哪些市场可用 |
| 话术 | 03、15、17、18 | 不同阶段怎么表达、何时升级、哪些内容不能承诺 |
| 报价 | 07、16 | 哪些变量影响价格、方案、样品、交期与审批 |
| 售后 | 05、19、20 | 如何定位问题、保留证据、分级处理并回写经验 |

这四个知识包只是岗位入口，不复制原始知识卡。所有入口必须引用同一 `kb_id`，避免产品参数、报价口径和售后责任出现多个版本。

## 3. 统一业务闭环

```text
渠道询盘/主动开发
  -> 归集与去重
  -> 验真、背调与资格判断
  -> 负责人分配和下一步任务
  -> 挖需、方案、报价与审批
  -> 谈判、订单、交付与回款
  -> 售后、复购与转介绍
  -> 赢输单/异常复盘
  -> 知识更新候选
```

闭环要求：

1. 渠道可以不同，客户、商机、许可、评分和移交标准必须统一。
2. 每一步都必须留下输入来源、输出物、负责人、截止时间、完成证据和异常升级路径。
3. 自动化只能推进已批准的标准动作；退订、黑名单、欠款、争议和审批红线优先于评分。
4. 复盘先生成知识更新候选，不直接覆盖已验证事实。

## 4. 四阶段上线闸门

| 阶段 | 先交付什么 | 进入下一阶段前必须证明什么 |
|---|---|---|
| 1. 知识库底座 | 来源、产品、话术、报价、售后、权限与红线 | 高频问题有可追溯答案；未批准事实不能对外；缺口已进入确认队列 |
| 2. 业务工作流 | 先跑通一个高频场景和人机分工矩阵 | 周期、准确率或漏跟进相对基线有可复核改善；高风险动作仍由人审批 |
| 3. 运营数据 | 多渠道归集、去重、状态和异常提醒 | 数据来源一致、异常可发现、周报可复算、失败可回滚 |
| 4. 管理决策 | 基于业务事实的看板、复盘和资源决策 | 指标可追溯到原始记录；管理动作和结果可回看；至少完成一个复盘周期 |

阶段顺序固定，周期不固定。培训材料中的周数、正确率和自动化率只能作为候选目标；每家企业必须先测基线，再由负责人确认阈值。

## 5. 验收指标

- **知识可信**：来源覆盖率、人工确认率、过期率、冲突数、未审批公开数。
- **业务转化**：首次响应、背调/报价周期、有效商机率、样品转单、赢单、复购和回款。
- **运营质量**：重复记录率、分配失败、超期任务、异常发现时间、自动化失败与人工接管率。
- **管理采用**：周报可复算率、审批时效、决策动作完成率、复盘后规则更新效果。

除安全硬门槛外，指标必须记录基线、目标、观察窗口、数据来源和负责人；没有真实运行数据时只报告 `NOT_RUN`，不推算收益。
